# Security Checklist

- Enrollment tokens are one-time visible secrets.
- Personal CLI profiles use hidden TTY or explicit bounded stdin, required PAT session validation, owned Unix mode600 atomic files and server-origin scoping. Redirects and unsafe/symlink/hardlink profiles are rejected. No remote password login/storage is added; expired/invalid/revoked credential errors do not imply Job failure. Actual scoped HTTPS two-user/API/CLI and Linux-Agent acceptance has passed.
- Bootstrap admin token maps to an authenticated admin actor and role before protected APIs run.
- Dangerous admin APIs check route permissions and return 403 with the required permission when denied.
- Owner account metadata collection/detail have explicit current-owner use cases and bounded SQL pages, including lookahead validation and no GET cleanup/renewal. Valid admin/operator/viewer callers are forbidden, even for their own administrative-detail URL. Cursor purpose/version/owner, query bounds, unknown body and malformed stored rows fail closed. SQLite and owned PostgreSQL shared contracts cover the adapter; actual scoped IAM/browser acceptance also has passed.
- Owner create/change/reset HTTP requires same-request password proof, shared finite CPU/actor-name admission, current commit authority and last-owner protection. Actual HTTP tests cover role/disable/reset revocation, same-value/metadata preservation, once-returned grants and replay refusal, non-owner/forged/null/duplicate input refusal, private audit rollback and cancelled/revoked late proofs. Own revocation clears the cookie; other people remain authenticated. Scoped HTTPS self-reset is covered; own password replacement/PAT issuance/metadata/revocation also pass real HTTP, while the guarded business writes and actual scoped browser/Linux-Agent acceptance also pass.
- Command/DriftCheck/direct-and-catalog-Runbook creation and approval/rejection recheck personal/legacy authority within the same SQLite immediate or Postgres identity-locked transaction as their effects. Real HTTP tests cover stale contexts after logout/disable, A-request/B-decision immutable audit actors, self approval, duplicate refusal and private audit/Job-metadata faults with full rollback. Actual owned PostgreSQL covers the shared Command/decision contract and approval audit/Job-status failure rollback. The other scoped business guards and actual browser/Agent acceptance also pass.
- Explicit human cancellation now derives JobCancel authority and immutable audit actor at the same transaction as conditional assignment/Job changes. Native HTTP covers logout refusal, full rollback at the second assignment/Job/audit writes, redacted reasons and repeat no-op. A bounded session-queue test proves an audit rollback sends no cancellation; existing dispatch/reopen and late-final receipt tests remain green. Actual owned PostgreSQL shares the two-target authority/fault and canceled-Job approval-conflict contract; this does not imply Agent receipt or full product acceptance.
- Manual approval expiry rechecks the human JobApprove credential and commits its bounded batch atomically. SQLite/actual owned Postgres tests cover expiry-minus-one/exact-boundary, logout refusal, partial-batch approval/Job/audit faults, immutable actor, repeat no-op and canceled-Job preservation. The existing 500-pending scan is unchanged; no scheduler or Agent delivery is added.
- IAM-001 foundations have deterministic account/credential and rollback Application tests plus fixture-only actual crypto tests. Fixed Argon2id cost, NFC/input bounds, unique salts, constant-time comparison, owned wiped scratch, token purpose separation and redacted errors are implemented in crate-private primitives. Worker tests verify one/two active threads, one pending slot, bounded unread replies, fixed deadline/cancellation and joined shutdown/Drop/fault paths. HTTP composition now consumes the identity repository and worker without retaining the shared store mutex during KDF. Personal login/session/logout, setup and cookie/PAT/Origin/CSRF have owned loopback HTTP coverage. Command, DriftCheck, direct/catalog Runbook and approval/rejection, cancellation, manual expiry and remediation approval/job guards are connected; personal UI is connected with scoped native HTTP/DOM checks; personal-token CLI input/profile is connected; real scoped two-user HTTPS acceptance has passed; these tests are not a release acceptance substitute.
- SQLite and feature-gated Postgres v28 identity tests cover additive v27 history preservation, atomic schema/version and account/audit rollback, mode-conditional shared-token rejection, immutable identity/credential lifecycle fields, commit-time owner availability and corrupt-row rejection. Missing v28 identity objects are errors, never a trigger to recreate shared-token access. The shared App flows and owner/claim/revocation races passed on actual owned PostgreSQL18.3; actual restore and session/PAT quota/cleanup/self-service contracts pass; scoped two-user HTTPS acceptance passes; Controller Postgres readiness remains unsupported.
- Application human-restore invalidation now passes four-purpose stale-binding and account/verifier/history preservation, failed entropy/authority/audit rollback, local-setup mode and independent epoch tests. SQLite and actual owned Postgres shared contracts also preserve Agent/delivery history and reject revived shared-token access. CLI file integration now passes actual two-epoch restore, four-purpose rejection, history/key preservation, audit rollback and atomic filesystem/owned process-kill contracts. Fresh official-binary recovery/restore, safety-backup rollback, corrupt/audit-fault target preservation, busy offline commands and old-backup local setup pass on the marked fixture. Owned loopback personal HTTP authentication now has separate evidence; scoped two-user HTTPS acceptance has passed. Synthetic lookup seeds are not HTTP login evidence.
- Local recovery CLI tests pass real target password replacement, selected-person session/PAT revocation, other-person isolation, UID-derived audit, custom DB selection and busy/unsafe/cancelled/weak-input rejection. Missing or mismatched original signing material fails before password input and cannot regenerate trust. Owned native recovery/restore rehearsal passes; scoped two-user HTTPS acceptance has passed.
- Core lease tests cover private Unix directory/lock ownership and modes, symlink/hardlink/special-file rejection, process contention, redacted diagnostics and explicit Drop release with duplicated descriptors. Actual Controller startup tests cover default/custom DB exclusion before access, unsafe-directory rejection without repair, failure release, healthy runtime and shutdown. Local CLI composition tests cover actual first-owner KDF/SQLite cutover, UID audit actor, shared DB settings, private init/demo and missing-key preservation. PTY tests cover hidden bounded input, cancellation, confirmation, line-tail discard and restoration without output-drain blocking. The official-binary loopback rehearsal passes legacy positive authentication, precommit SIGKILL/lease release, concurrent cutover with exactly one success, audit-fault rollback, restart rejection of the old bearer and identity/history preservation. Scoped personal-login HTTPS acceptance has passed; the lease does not prove an older nonparticipating binary has stopped.
- Output-page reads retain `job_read` authorization, strict scoped cursor/query validation, source/JSON limits and no-store responses. Restore/retention changes return explicit stale errors; the cursor is neither a credential nor a signed integrity proof. Current roles all have JobRead; no additional role is invented for this endpoint.
- Matching authenticated recurring heartbeats refresh stored inventory receipt time and preserve degraded health. Payload Agent-ID mismatch cannot refresh another Agent; valid ticks do not emit unexpected-message Security audits.
- Actual authentication-load evidence combines bounded worker/admission tests with typed busy429, bounded process RSS observations, protected reads and a Linux Agent Job/heartbeat comparison. It is not internal queue telemetry or a production SLA.
- Agent identity is key-pair based.
- Controller identity is key-pair based.
- Agents pin the controller public key after enrollment.
- The active WebSocket protocol is v2 only: version mismatches are rejected before payload parsing, with no v1 fallback. Upgrade Controller and all Agents together. `auth_accepted` binds the durable delivery namespace/epoch to the expected Agent and handshake correlation; the persistent Agent journal owner is bound to namespace plus Agent ID, and receipt verification uses the current session epoch.
- Task assignments use controller-signed envelopes.
- A successful remediation creates at most one signed verification assignment through the durable Job/assignment/correlation/audit transaction; dispatch occurs only after commit. Before listener readiness, bounded scans create only correlation-free verification Jobs and resolve only persisted successful-final/fresh-compliant-evidence pairs; unverifiable legacy rows are audit-skipped. Resolution rechecks correlation and updates only the origin drift, and a repeated scan does not duplicate the resolution audit.
- High-risk commands require explicit confirmation.
- HTTP transport is test-only, emits warnings, and writes Security audit when configured as the controller external URL.
- Product, customer, production, shared, and long-running environments use HTTPS.
- Product logs do not include command output or secret values.
- Catalog sync status is a protected, source-scoped, no-store read with classified failures; HTTP 202 is acceptance, and neither a status read nor sync completion activates a revision.
- The internal catalog Job creation port atomically persists pending approval, provenance audits, signed assignments/targets and settings after rechecking the exact active/ready document. The catalog-reference HTTP caller enforces JobCreate/PolicyRead, authenticated actor, strict body-free input and target/capability preflight; no dispatch precedes commit and approval. Job detail exposes only its immutable provenance snapshot.
- Darwin/Linux command output failure, cancellation and timeout clean up the newly owned process group before returning; output polling avoids unbounded reader queues and inherited-pipe joins. Group cleanup uses an unreaped leader, never a PID recovered from disk. Already-completed side effects and escaped daemons are not rolled back.
- Persistent TaskAck/TaskStarted/TaskRejected, DriftCheck evidence and terminal result, Command stdout/stderr, no-artifact Runbook stdout/stderr, and no-artifact Command/Runbook finals are committed to the owner-only Agent journal before v2 send, replayed after reconnect, and removed only after the exact signed `stored` receipt verifies. Controller owner checks and SQLite transactions commit lifecycle transitions, Job aggregate, audit, and inbox marker together; TaskRejected only moves an owned `dispatched` Assignment to `rejected`. DriftEvidence commits correlated evidence and eligible proposal effects but is not Job/Assignment success; DriftCheck terminal result is a separate final effect. Duplicate reports do not repeat effects, and terminal Assignment state is never downgraded. The journal enforces effective-user ownership/owner-only Unix modes and redacts report bodies from Debug/errors. Persistent Command/no-artifact Runbook finals require exact stored per-stream `[0, count)` coverage and reject truncated success; this confirms journaled chunks, not capture of every task output byte. Artifact-bearing Runbook finals use a strict v2 Controller effect/receipt path, but artifact output/final bytes are not in the Agent journal and cannot be replayed after a pre-inbox disconnect. Direct one-shot `heartbeat --once` also remains outside the Agent journal path. Controller G2 recovery is SQLite-only: bounded startup/30-second scans mark overdue assignments outcome-unknown without replay; Postgres startup fails closed until it implements the contract.
- Persistent Command and no-artifact Runbook require durable Agent admission after signed-envelope and nonce checks, followed by a committed start intent before TaskAck/TaskStarted and host effects. The journal atomically retains per-stream committed output counts through individual output receipt cleanup, and final-result insertion must match them before marking execution complete. A new process or idle runtime after the prior task owner ends converts admitted/start-intent records to typed failed final reports with exact stored counts, without rerunning the task; reconnect while the task owner is live skips recovery. A matching no-artifact Command, Runbook, or DriftCheck final arriving after SQLite G2 marked its owner `failed/execution_outcome_unknown` gets one durable disposition/audit and a signed receipt without changing terminal state; exact retry is idempotent. Artifact-producing Runbook final output remains non-durable; its v2 final effect and already-staged pending Controller reports are recovered on SQLite, but Agent-side report replay, one-shot and Drift execution recovery remain outside this integration. DriftEvidence and terminal result delivery are durable for persistent sessions.
- Agent journal schema v4 adds DriftEvidence and preserves existing v3 report rows/bytes; v3 upgrades local v1/v2 data additively. A v2 journal with active `StartIntent` fails closed before schema or stored-report changes; finish that task under the existing Agent before upgrading so previously ACK-cleaned output cannot invalidate exact final coverage. This local data migration does not imply old wire-protocol compatibility.
- An owner-matching TaskAck/TaskStarted/TaskRejected after SQLite G2 set `failed/execution_outcome_unknown` gets one terminal-preserving late disposition: redacted Job audit and inbox marker commit atomically, then an exact signed `stored` receipt is persisted/replayed. Assignment, Job aggregate, and G2 reason do not change; the receipt does not mean the task succeeded. Owner mismatch and changed bodies fail closed, while this receipt allows ordered Agent replay to continue. The dispatched-cancellation exception below also preserves canonical terminal state.
- Journal worker tests enforce commit-before-completion, bounded outstanding requests/replies, nonblocking session polling, and joined shutdown. Wait timeout is not cancellation or execution permission; receipt authentication remains the session adapter's responsibility.
- Receipt verifier tests require pinned/rotated Ed25519 trust, exact Controller namespace/store epoch/report digest, and a `stored` disposition. Controller schema v23 persists namespace/epoch and actual restore rotates the epoch; the v2 authenticated handshake transfers both values to the Agent. The journal binds namespace and Agent ID; an old-epoch receipt cannot clean a still-pending report. Exact pending replay can receive a current-epoch receipt when the restored DB still has the matching owner-bound effect, without repeating it. Missing owners fail closed. Reports already ACK-cleaned before the restored snapshot cannot be recovered and require external reconciliation.
- Controller schema v24 SQLite inbox checks Assignment owner and per-Agent pending quota before storing exact report bytes; a pending row never produces an ACK. Schema v25 stores signed receipt bytes for an exact committed key/digest; v26 adds `drift_evidence` while preserving inbox rows and receipt foreign keys. After a signing-key rotation, the authenticated Controller helper may replace old receipt bytes only with a verified current-key receipt for the same committed digest/epoch; the report effect is not repeated. Stale epoch, changed digest/owner, uncommitted row, and invalid signature fail closed. Agent accepts the prior signer only during trust grace. The live authenticated Controller session supports SQLite TaskAck/TaskStarted/TaskRejected lifecycle, DriftEvidence, output, and Command/Runbook/DriftCheck final-result effects including artifact-bearing Runbook finals, and fails closed on Postgres. Remediation final-result follow-up and Postgres report recovery remain unsupported.
- A previously dispatched canceled Assignment can disposition an exact-owner lifecycle report or supported no-artifact Command/Runbook final without changing canonical status, reason, completion time, Job aggregate or output. Finals require exact output coverage and no remediation effects; valid completion outcomes racing cancel are recorded as dispositions, never applied as success overrides. Audit/inbox rollback, exact signed receipt/reopen replay, wrong-owner/body, undispatched/other-terminal, output-gap and unsupported-final guards are verified separately. Agent journal deletion still requires the exact verified receipt.
- The live SQLite report path commits TaskAck acceptance, TaskStarted start, pre-execution TaskRejected (Assignment/Job/audit/reason), DriftEvidence (correlated row/audit/eligible remediation proposal), output chunks, or supported final-result Assignment/Job/audit effects with the inbox marker atomically, persists a signed `stored` receipt, and queues it through the session's single writer. Identical retries replay the same receipt without duplicating effects; conflicting body or authenticated owner mismatch is rejected and Security-audited. Persistent TaskAck/TaskStarted/TaskRejected for Command/Runbook/Drift, DriftCheck evidence and its separate terminal result, Command/no-artifact Runbook stdout/stderr, and no-artifact Command/Runbook final results use the Agent journal/replay path. Artifact-bearing Runbook finals use the v2 Controller effect/receipt path but are not journaled/replayed by the Agent; direct one-shot remains separate.
- A strict persistent Command or no-artifact Runbook final requires locally journaled stdout/stderr counts. SQLite checks the exact per-stream prefix before final Assignment/Job/audit effects or a receipt; gaps keep the final pending for retry. Truncation and counts are the only output values copied into the Job audit, and a truncated final cannot succeed. This is a delivery barrier, not proof that task execution emitted no uncaptured bytes.
- SQLite pending-final effect scans are bounded to 100 rows/8 MiB of bodies and verify digest and Assignment owner after reopen. Startup and periodic recovery apply supported effects through the same prepared transaction; receipts are persisted only after commit and are queued to an active session through its single writer. A separate bounded scan of up to 100 committed final identities missing a receipt reads only key/digest and issues no repeated effect. Corrupt/owner-mismatched rows, output gaps, unsupported follow-up, and terminal assignments fail closed and remain pending. Recovery reads do not mutate inbox state or authorize receipts by themselves.
- SQLite prepared Command/Runbook/DriftCheck final effect commits relevant artifact metadata/Assignment/Job/audit/inbox marker atomically; injected metadata/marker/audit failures roll all DB effects back and duplicate commit repeats no effect. The live Controller connects supported Command/Runbook finals—including artifact-bearing Runbook bodies—and persistent DriftCheck terminal results to this transaction and receipt flow. A body put precedes the SQLite transaction and can leave an orphan file on failure; retry is handled by bounded startup/periodic recovery after staging. Prepared remediation execution status/Policy audit join the same transaction and `succeeded_pending_verify` is recovered into one verification Job after reopen. DriftEvidence commits a correlated drift row/redacted audit/eligible proposal and inbox marker only after exact staged bytes, Assignment owner and stored provenance checks; final and evidence order is independent. Remediation final-result follow-up remains unconnected.
- Local artifact put is immutable per ID/class: same-body replay succeeds; changed/corrupt existing body is not overwritten. Owner-only temporary body is fsynced before no-clobber publish. Temporary/orphan cleanup and DB/file recovery are still pending.
- Controller TaskRejected/TaskResult control transitions reject authenticated Agent or claimed Job mismatch transactionally and record Security audit; persistent TaskAck/TaskStarted/TaskRejected are owner-bound v2 Lifecycle reports with atomic SQLite effects and exact signed receipts. Agent-side durable receipt handling covers persistent TaskAck/TaskStarted/TaskRejected, DriftEvidence and terminal DriftCheck results, Command/no-artifact Runbook output, and no-artifact Command/Runbook final results. Artifact-bearing Runbook final effect/receipt is supported at the Controller but Agent replay is not; direct one-shot delivery also remains pending.
