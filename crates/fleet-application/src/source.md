# Fleet Application Source Index

`fleet-application` owns use-case orchestration and repository contracts between the domain and interface/infrastructure layers.

| Path | Kind | Responsibility | Boundary / Side effects |
| --- | --- | --- | --- |
| `admin_remediation.rs` | Application | Prepares human remediation approval requests/execution and commits exact prior-state comparisons, current authority and every effect through the approval transaction. | Signing precedes locks; immutable actor/audit and approval deadline guards, no direct I/O or automatic replay. |
| `admin_cancel.rs` | Application | Selects cancellable assignments and prepares canonical aggregate state, human audit and post-commit dispatch candidates. | Injected redaction precedes the transaction; current authority and every durable cancellation effect share a rollback boundary. No transport I/O. |
| `admin_catalog.rs` | Application | Connects immutable catalog preparation to a required human-authorized composite commit and server-derived actors. | Narrow read-only execution view; signatures precede canonical authority/catalog validation, no direct I/O or trusted-write fallback. |
| `structured_job.rs` | Application | Prepares validated DriftCheck/Runbook values and orchestrates human-authorized creation through a required composite port. | Injected signer runs before the protected transaction; shared audit construction and current authority checks, no direct persistence, transport or dispatch I/O. |
| `admin_approval.rs` | Application | Applies server-derived authority to approval/rejection and bounded manual expiry through the atomic callback shared with remediation. | Revalidates current identity and time in the same transaction as approval, pending Job status and audit; no I/O or dispatch. |
| `admin_write.rs` | Application | Owns typed personal/legacy mutation principals, fresh permission/binding/mode checks and request-local ordered UTC observations. | Requires the same canonical transaction as the effect; returns identity metadata without a reusable permission grant. No SQL, KDF or configuration I/O. |
| `admin_write_tests.rs` | Test | Verifies current personal/legacy authority, revocation/role/epoch/expiry and clock rollback across protected preparation/commit. | Controlled standard-library identity/clock/signer ports only; no actual database or runtime acceptance claim. |
| `command_job.rs` | Application | Prepares Command Job effects and owns the required atomic protected-creation port/use case, canonical actor binding and shared Job selector/strategy metadata/commit errors. | Signs before persistence; legacy orchestration keeps its ordering, while protected creation requires current authority and all supplied effects to commit together. No direct I/O or dispatch. |
| `admin_auth.rs` | Application | Owns fixed session/PAT issuance, current password proof, scoped metadata, logout/revocation and bounded retired-lookup reclamation. | Explicit password/entropy/repository/clock ports; no SQL, HTTP, environment or raw-secret diagnostics. |
| `admin_auth_tests.rs` | Test | Verifies valid-first login/expiry, real/dummy proof contracts, current-account/clock/deadline races, physical/user quotas, scoped metadata, logout/revocation and bounded cleanup progress. | Controlled std-only ports and atomic in-memory fixtures; no actual crypto, browser or production database. |
| `admin_identity.rs` | Application | Owns human account use cases, human-only restore invalidation, and typed repository, crypto/epoch, operation and local-authority ports. | Canonical account/auth-mode/credential/audit transactions; password/entropy work occurs outside transactions and current authority is checked before commit. Restore changes only human mode/epoch/audit and preserves account/verifier/credential history. |
| `admin_account_query.rs` | Application | Defines bounded owner-only account metadata collection/detail reads and their page query port. | Revalidates current human authority around reads; explicit summaries exclude verifier/credential material, without I/O or canonical writes. |
| `admin_identity_tests.rs` | Test | Exercises human identity use cases with rollback transactions, synthetic crypto, non-recycled entropy, authority and race fixtures. | In-memory fixtures only; does not prove actual OS locks, database serialization or cryptographic strength. |
| `admin_restore_tests.rs` | Test | Verifies four-purpose credential invalidation, account/verifier/history preservation, local-setup mode, authority/entropy/audit failure rollback and concurrent epoch rejection. | Reuses in-memory identity fixtures; no actual filesystem restore, Agent state or OS authority claim. |
| `catalog_execution.rs` | Application | Resolves catalog Job target snapshots, validates known Runbook/step capabilities and defines immutable Job provenance reads. | Pure policies and read port; no I/O, authorization, catalog fetch, persistence mutation or dispatch. |
| `output_read.rs` | Application | Defines validated output scope, cursor positions, fragment/source budgets, redacted fragments and a bounded page read port/use case. | No I/O or serialization; adapters must validate persisted ownership, restore/retention context and a consistent canonical status/output snapshot. |
| `delivery.rs` | Application | Defines immutable report bodies, Agent journal and Controller inbox/output/TaskAck/TaskStarted/TaskRejected/evidence/prepared-artifact/remediation final-effect/final-recovery ports, committed-final receipt-recovery candidates, per-task output summary contract, typed normal and terminal-preserving G2/cancellation effect outcomes, signed-receipt persistence/replay and current-signer reissue contracts, Controller delivery identity/restore rotation port, and queue/confirmation/admission/start use cases. | No direct I/O; authenticated inbox owner/body admission, nonce verification before Agent execution, terminal-preserving late-report disposition, body-redacted diagnostics, bounded replay reads, bounded key/digest-only recovery for committed finals missing receipt bytes, and verified current-key receipt replacement for an exact committed report. Evidence effects may carry a validated remediation proposal for the same atomic Store transaction. |
| `assignment_recovery.rs` | Application | Defines a bounded Controller recovery pass for overdue active assignments and its conditional repository contract. | Revalidates the domain deadline; requests atomic transition to failed with typed outcome-unknown reason and never replays a task. |
| `lib.rs` | Application | Defines use cases and typed repository ports, including durable catalog reads and source-scoped sync-operation status, catalog registration/sync, catalog-only creation preparation through a narrow execution read view and required composite write port, signed Job publication, verified drift validation, Agent/Job-owned composite remediation persistence, and bounded remediation-verification resolution recovery. | Performs no direct I/O; callers provide repository, audit, signer, clock, fetcher, and dispatcher adapters. Catalog creation prepares approval/audits/selector/strategy before one atomic-write request; the port does not dispatch or provide a sequential fallback. |
